**Branches** in der Seitenleiste (⌘3) zeigt die Branches der Repositories, denen du folgst, als Baum: pro Repository oben der Standard-Branch und jeder andere Branch unter dem Branch, aus dem er erstellt wurde. Der Bereich beantwortet eine Frage, die die Listen PRs und Tags nicht beantworten: Wer arbeitet woran, bevor es einen Pull Request oder Tag gibt.

## Der Baum

Jedes Repository ist eine Gruppe, die du mit einem Klick auf den Namen einklappst; daneben steht, wie viele Branches heute einen Push bekamen. Darunter:

- Der Standard-Branch, markiert mit **Standard**.
- Jeder Branch unter dem Branch, aus dem er erstellt wurde, beliebig tief. Der neueste Push steht oben.
- **Wer**: wer zuletzt gepusht hat, mit Bild. Ein Klick auf einen Namen zeigt nur dessen Branches.
- **Voraus / Zurück**: ↑3 ↓1 heißt drei Commits, die der Ursprung nicht hat, und ein Commit des Ursprungs, den dieser Branch noch nicht hat.
- **Letzter Push**, mit einem Punkt, wenn er in der letzten Stunde war.
- Eine Pille mit der Nummer eines offenen Pull Requests, und **Neuer Branch** oder **Force-Push**, wenn das am letzten Tag geschah.

## Woher Pullwatch weiß, woher ein Branch kommt

Git und die Dienste speichern nicht, aus welchem Branch ein Branch erstellt wurde. Pullwatch ermittelt es in dieser Reihenfolge:

1. Der Ziel-Branch eines offenen Pull Requests von diesem Branch.
2. Sonst der Verlauf: der Branch, dem er die wenigsten Commits voraus ist, so wie Git es selbst vorschlägt.
3. Sonst der Standard-Branch.

Der Inspektor sagt, welcher der drei Wege es war. Das kostet ein paar Anfragen pro neuem Branch, daher braucht ein Repository mit vielen neuen Branches manchmal ein paar Abrufe, bis alles an seinem Platz ist; bis dahin hängt so ein Branch unter dem Standard-Branch.

## Der Inspektor

Wähle einen Branch, um ihn rechts zu sehen: den Pfad ab dem Standard-Branch, **Mit Ursprung vergleichen** (der Vergleich beim Dienst), **Im Browser öffnen** und **Branch-Namen kopieren**. Darunter **Erstellt aus** mit der Herkunft dieser Angabe, wie weit der Branch von seinem Ursprung und vom Standard-Branch entfernt ist, sein Pull Request und der letzte Push. **Aktivität** listet die Pushes, die Pullwatch gesehen hat; jeder öffnet seinen Vergleich.

Pullwatch sieht, was sich zwischen zwei Abrufen geändert hat, nicht jeden einzelnen Push. Drei Pushes zwischen zwei Abrufen sind ein Eintrag mit allen neuen Commits.

## Suchen und Filter

Suche nach Branch, Repository oder Person. Die Symbolleiste filtert nach einem Repository oder einer Person; **Nur andere** blendet die Branches aus, auf die du zuletzt gepusht hast. Ein gefundener Branch behält die Branches über ihm, damit du siehst, wo er hängt.

**Gelöschte Branches** zeigt auch gemergte oder gelöschte Branches, abgeblendet und durchgestrichen, solange der Verlauf aufbewahrt wird. **Neu laden** liest die Branches sofort; der Untertitel sagt, wann sie zuletzt geprüft wurden.

Pullwatch erkennt deine eigenen Pushes an deinem Konto auf GitHub, und auf Bitbucket und Gitea, wo das Konto mit der Person verknüpft ist. Sonst vergleicht es Name und E-Mail-Adresse des Autors mit deinen.

## Keine Mitteilungen

Pushes lösen nie eine Mitteilung aus, zählen nicht als ungelesen und erscheinen weder im Menüfenster noch im Dock-Badge. Das ist eine Liste zum Nachsehen, kein Strom, dem man folgen muss.

## Branches folgen

Branches folgen zusammen mit den Pull Requests, pro Repository: Setzt du für ein Repository den Haken bei **PRs**, ist auch **Branches** an, und entfernst du den Haken bei **PRs**, sind beide aus. Um nur die Branches eines Repositorys auszuschalten, entferne den Haken bei **Branches** in der Repository-Liste des Kontos (Einstellungen, Konten) oder unter **Folgen** in der **Übersicht** des Repositorys. Solange die Liste noch leer ist, hat der Bereich eine Taste **Branches folgen**, die Einstellungen, Konten öffnet.

Branches werden höchstens alle 15 Minuten gelesen, getrennt von Pull Requests und Tags. Ein Rate Limit bei Branches hält Pull Requests oder Tags nie auf: Sie kommen wie gewohnt an, und Branches warten, bis das Limit vorbei ist. Pushes bleiben so lange erhalten wie der Verlauf (Einstellungen, Allgemein, **Verlauf behalten**).
