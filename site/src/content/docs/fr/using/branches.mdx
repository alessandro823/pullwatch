**Branches** dans la barre latérale (⌘3) montre les branches des dépôts que vous suivez sous forme d'arbre : pour chaque dépôt, la branche par défaut en haut, et chaque autre branche sous la branche à partir de laquelle elle a été créée. La section répond à une question que les listes PRs et Tags ne couvrent pas : qui travaille sur quoi, avant qu'il y ait une pull request ou un tag.

## L'arbre

Chaque dépôt est un groupe que vous repliez d'un clic sur son nom ; à côté, le nombre de branches qui ont reçu un push aujourd'hui. Dessous :

- La branche par défaut, marquée **par défaut**.
- Chaque branche sous la branche à partir de laquelle elle a été créée, sur autant de niveaux que nécessaire. Le push le plus récent vient en premier.
- **Qui** : la dernière personne qui a poussé, avec sa photo. Cliquez sur un nom pour ne voir que ses branches.
- **Avance / Retard** : ↑3 ↓1 signifie trois commits que l'origine n'a pas, et un commit de l'origine que cette branche n'a pas encore.
- **Dernier push**, avec un point s'il date de la dernière heure.
- Une pastille avec le numéro d'une pull request ouverte, et **Nouvelle branche** ou **Force push** si c'est arrivé dans la journée.

## Comment Pullwatch sait d'où vient une branche

Git et les services n'enregistrent pas à partir de quelle branche une branche a été créée. Pullwatch le déduit dans cet ordre :

1. La branche cible d'une pull request ouverte depuis cette branche.
2. Sinon l'historique : la branche dont elle a le moins de commits d'avance, comme Git le propose lui-même.
3. Sinon la branche par défaut.

L'inspecteur indique laquelle des trois s'applique. Cela demande quelques requêtes par nouvelle branche ; un dépôt avec beaucoup de nouvelles branches peut donc demander quelques lectures avant que tout soit à sa place, et d'ici là une telle branche reste sous la branche par défaut.

## L'inspecteur

Choisissez une branche pour la voir à droite : le chemin depuis la branche par défaut, **Comparer avec l'origine** (la comparaison chez le service), **Ouvrir dans le navigateur** et **Copier le nom de la branche**. En dessous, **Créée à partir de** avec la façon dont Pullwatch le sait, la distance de la branche à son origine et à la branche par défaut, sa pull request et le dernier push. **Activité** liste les pushs que Pullwatch a vus ; chacun ouvre sa comparaison.

Pullwatch voit ce qui a changé entre deux lectures, pas chaque push séparé. Trois pushs entre deux lectures font une seule entrée avec tous les nouveaux commits.

## Recherche et filtres

Cherchez par branche, dépôt ou personne. La barre d'outils filtre sur un dépôt ou une personne ; **Seulement les autres** masque les branches où vous avez poussé en dernier. Une branche trouvée garde les branches au-dessus d'elle, pour que vous voyiez où elle se place.

**Branches supprimées** montre aussi les branches fusionnées ou supprimées, estompées et barrées, tant que l'historique est conservé. **Recharger** lit les branches tout de suite ; le sous-titre indique quand elles ont été vérifiées pour la dernière fois.

Pullwatch reconnaît vos propres pushs grâce à votre compte sur GitHub, et sur Bitbucket et Gitea quand le compte est lié à la personne. Sinon il compare le nom et l'adresse e-mail de l'auteur avec les vôtres.

## Pas de notifications

Un push ne déclenche jamais de notification, ne compte pas comme non lu et n'apparaît ni dans le panneau du menu ni sur le badge du Dock. C'est une liste à consulter, pas un flux à suivre.

## Suivre les branches

Les branches sont suivies avec les pull requests, dépôt par dépôt : cocher **PR** pour un dépôt coche aussi **Branches**, et décocher **PR** décoche les deux. Pour désactiver seulement les branches d'un dépôt, décochez **Branches** dans la liste des dépôts du compte (Réglages, Comptes) ou sous **Suivre** dans l'**Aperçu** du dépôt. Tant que la liste est vide, la section a un bouton **Suivre les branches** qui ouvre Réglages, Comptes.

Les branches sont lues toutes les 15 minutes au plus, séparément des pull requests et des tags. Une limite de débit sur les branches ne retient jamais les pull requests ni les tags : ils arrivent comme d'habitude, et les branches attendent la fin de la limite. Les pushs sont conservés aussi longtemps que l'historique (Réglages, Général, **Conserver l'historique**).
