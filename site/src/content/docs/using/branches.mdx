**Branches** in the sidebar (⌘3) shows the branches of the repositories you follow as a tree: per repository the default branch at the top, and every other branch under the branch it was made from. It answers a question the PRs and Tags lists cannot: who is working on what, before there is a pull request or a tag.

## The tree

Each repository is a group you can fold with a click on its name; next to it, how many branches got a push today. Under it:

- The default branch, marked **default**.
- Every branch under the branch it was made from, any number of levels deep. The most recent push comes first.
- **Who**: the person who pushed last, with their picture. Click a name to see only their branches.
- **Ahead / Behind**: ↑3 ↓1 means three commits the parent does not have, and one commit of the parent this branch does not have yet.
- **Last Push**, with a dot when it was in the past hour.
- A pill with the number of an open pull request, and **New Branch** or **Force Push** when that happened in the past day.

## How Pullwatch knows where a branch came from

Git and the services do not record which branch a branch was made from. Pullwatch works it out in this order:

1. The target branch of an open pull request from the branch.
2. Otherwise the history: the branch it is the fewest commits ahead of, which is how Git itself suggests finding it.
3. Otherwise the default branch.

The inspector says which of the three it was. Working it out takes a few requests per new branch, so a repository with many new branches can need a few reads before every branch is in its place; until then such a branch hangs under the default branch.

## The inspector

Select a branch to see it on the right: the path from the default branch, **Compare with Parent** (the comparison at the service), **Open in browser** and **Copy Branch Name**. Below that, **Made from** with how Pullwatch knows, how far the branch is from its parent and from the default branch, its pull request and the last push. **Activity** lists the pushes Pullwatch saw, each opening its comparison.

Pullwatch sees what changed between two reads, not each separate push. Three pushes between two reads are one entry with all the new commits.

## Search and filters

Search by branch, repository or person. The toolbar filters on a repository or a person; **Others Only** hides the branches you pushed to last. A branch that matches keeps the branches above it, so you still see where it hangs.

**Deleted Branches** also shows branches that were merged or deleted, dimmed and crossed out, as long as the history is kept. **Reload** reads the branches right away; the subtitle says when they were last checked.

Pullwatch recognises your own pushes by your account on GitHub, and on Bitbucket and Gitea where the account is linked to the person. Otherwise it compares the name and the e-mail address of the author with yours.

## No notifications

Pushes never notify you, do not count as unread, and do not show in the menu panel or the Dock badge. This is a list to look at, not a stream to keep up with.

## Following branches

Branches follow along with pull requests, per repository: ticking **PRs** for a repository also ticks **Branches**, and clearing **PRs** clears both. To switch off only the branches of a repository, clear its **Branches** checkbox in the account's list of repositories (Settings, Accounts) or under **Follow** on the repository's **Overview**. While the list is still empty, the section has a **Follow Branches** button that opens Settings, Accounts.

Branches are read at most every 15 minutes, separately from pull requests and tags. A rate limit on branches never holds back pull requests or tags: those arrive as usual, and branches wait until the limit is over. Pushes are kept as long as the history (Settings, General, **Keep history**).
